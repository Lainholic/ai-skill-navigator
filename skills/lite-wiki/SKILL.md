# Lite-Wiki (초간단 플랫 위키 지식 관리 스킬)

> **"위키피디아처럼 주제별로 쌓되, 관리는 메모장처럼 가볍게. (Wikipedia structure with notepad simplicity.)"**

거대 위키 킷이나 RAG 시스템은 너무 복잡해서 결국 방치됩니다.  
`lite-wiki`는 **단일 `wiki/` 폴더** 안에 **전체 목차 파일(`INDEX.md`)**과 **주제별 마크다운 파일(`[주제명].md`)** 딱 2가지만 두는 **플랫(Flat) 위키 아키텍처**를 사용합니다.

---

## ⚡ 10초 적용법 (Zero-Install)

1. 이 `SKILL.md` 파일을 프로젝트의 `.agents/skills/lite-wiki/SKILL.md`에 넣습니다.
2. 프로젝트 루트에 `wiki/` 폴더를 만들고, 아래 `INDEX.md` 파일을 하나 생성합니다:

```markdown
# 📚 Project Wiki Index

- [프로젝트_아키텍처](./프로젝트_아키텍처.md): 시스템 전체 구조 및 기술 스택
- [코어_규칙](./코어_규칙.md): 절대 위반하면 안 되는 코딩/배포 철칙
- [외부_연동](./외부_연동.md): 결제, OAuth, 외부 API 스펙 및 정책
```

---

## 🛡️ 에이전트 2대 행동 수칙 (The 2 Core Rules)

이 스킬이 장착되면 AI는 지식을 다룰 때 오직 2단계로만 행동합니다:

### 1단계: 조회할 때 (Read Protocol)
* 환님/사용자가 특정 작업(예: *"결제 기능 수정하자"*)을 지시하면, AI는 먼저 **`wiki/INDEX.md`**를 훑어봅니다 (토큰 50개 미만 소모).
* `INDEX.md`에서 관련된 주제 파일(예: `wiki/외부_연동.md`)을 찾고, **해당 파일 1개만 정밀하게 읽어** 직전 결정과 스펙을 파악합니다.
* 무관한 다른 문서들을 마구잡이로 열어보지 않습니다.

### 2단계: 기록할 때 (Write Protocol)
* 작업이 끝나면, 관련된 **`wiki/[주제명].md` 파일 맨 아래에 오늘 날짜와 핵심 결정 3줄을 덧붙입니다(Append).**
* 만약 완전히 새로운 영역(예: '모바일_알림')이 생기면:
  1. `wiki/모바일_알림.md` 파일을 신설하고,
  2. `wiki/INDEX.md` 목차에 `- [모바일_알림](./모바일_알림.md): FCM 푸시 알림 연동` 한 줄을 추가합니다.

## 📂 폴더 구조 예시 (단일 플랫 구조)

복잡한 하위 폴더가 일절 없습니다:

```text
my-project/
├── src/
├── package.json
└── wiki/                         👉 단일 폴더
    ├── INDEX.md                  👉 전체 목차 (주제별 1줄 요약 링크)
    ├── 인증_인가_정책.md           👉 회원가입, JWT, OAuth 정책
    ├── 데이터베이스_스키마.md      👉 테이블 구조 및 인덱스 팁
    └── 배포_인프라.md             👉 도커, AWS, 환경변수 가이드
```

## 💡 왜 거대 위키보다 뛰어난가?

1. **에이전트가 분류로 고민하지 않습니다:**  
   `entities`, `concepts`, `sources` 같은 복잡한 카테고리가 없으므로, AI가 문서를 엉뚱한 폴더에 넣거나 헤매지 않습니다.
2. **1년이 지나도 유지됩니다:**  
   단일 파일 일기장 방식과 달리 **주제별로 파일이 분리**되어 있으므로, 1년 뒤에도 "인증 정책" 파일만 열면 몇 줄 안 되는 깔끔한 히스토리를 바로 볼 수 있습니다.
3. **완전한 무설치(Zero-Dependency):**  
   옵시디언, 파이썬 스크립트, 데이터베이스가 전혀 필요 없으며, GitHub 웹 UI나 메모장에서도 바로 읽고 수정할 수 있습니다.

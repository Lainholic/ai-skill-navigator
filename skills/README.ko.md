## 🚨 [필독] AI의 '자기 편향(Self-Confirmation Bias)'과 주의사항

### 1. 자기가 짠 코드를 자기가 검토할 때의 맹점
AI에게 *"방금 네가 짠 코드 검토해봐"*라고 하면, 높은 확률로 **"완벽합니다! 오류가 없습니다!"**라며 팔이 안으로 굽는 **자기합리화 편향(Self-Confirmation Bias)**이 발생합니다.
* AI도 자신이 생성한 토큰의 맥락에 갇히기 때문에, 논리적 맹점이나 숨겨진 버그를 스스로 찾지 못하고 정당화하려는 경향이 있습니다.
* `adversarial-review` 스킬은 AI에게 강제로 **"너는 이 코드를 파괴하러 온 해커이자 깐깐한 시니어 감사관이다"**라는 정반대의 적대적 페르소나를 부여해 이 편향을 최대한 깹니다.

## 💡 [Pro Tip] 한 단계 더 진화하기: "다른 모델 API 키 연동"

1인 2역 페르소나 전환도 훌륭하지만, **가장 완벽한 무결점 검증은 '완전히 다른 뇌(모델)'에게 코드를 던지는 것**입니다.

```
[메인 코더] Claude 3.5 Sonnet (코드 작성)
    ⬇
[적대적 비판관] DeepSeek-V3 또는 GPT-4o API (남의 눈으로 맹공 비판)
    ⬇
[최종 판정] 사람(사용자)의 선택적 채택
```

### 🛠️ 응용 방법:
* 메인 코딩을 **Claude**로 진행하고 있다면, 검증 단계에서 간단한 파이썬 스크립트나 curl 명령어로 **OpenAI(GPT-4o)** 또는 **DeepSeek API 키**를 호출해 코드를 던져보세요.
* *"나는 이 프로젝트와 아무 상관없는 제3자 감사관이다. 결함만 찾아내라"*는 프롬프트와 함께 다른 모델에 교차 검증을 시키면, 단일 모델이 절대 보지 못하던 기상천외한 엣지 케이스와 환각을 100% 잡아낼 수 있습니다.
